# 测试用例 Excel

用户要求输出测试用例时，交付真实可下载的 `.xlsx` 文件。默认中文，固定七列；用户本次明确要求优先。

## 写作原则：用产品语言写页面功能

- 面向使用产品的人写。读者不需要懂代码、数据库或自动化，也能知道“在哪个页面、操作哪个对象、点什么、应该看到什么”。句子简短，使用页面上的名称和用户能理解的词。
- 前置条件中的账号权限、套餐、已有记录和状态，应能在产品页面查看；步骤只能是用户能在页面完成的动作；预期结果必须能从页面内容、按钮状态、重新打开或刷新后的结果直接验证。输入数据写用户实际需要填写或选择的值。
- PR 和代码用来理解改动，不把实现细节抄进用例。不写接口地址、响应字段、数据库记录、服务名、队列、SSE、worker、fixture、Mock、挂起/释放后台任务、注入事件、定位器、回调、原子事务、teardown 等实现或自动化术语。页面本身使用的技术名称或用户明确要求的专有名称可保留。
- 用页面表现替代技术结论。例如写“刷新后仍显示新名称”，不写“数据持久化成功”；写“角色生成失败后可以重试”，不写“后台任务失败后释放并发槽位”。有明确产品数量限制时，直接写数量和能否继续创建。
- 不为方便自动化而添加产品没有的前置条件。检查“保存后弹窗关闭，角色继续生成”时，直接创建角色并观察卡片，不要求先暂停服务器任务。是否已有脚本、能否人为拖慢处理，不能成为编写普通页面用例的前置条件。
- 不强行把所有场景写成可自动执行。自动化是执行方式，不能改变产品验收要求。用户明确要求兼顾 Playwright 时，再读取 [页面用例与自动化的边界](references/playwright-executability.md)；技术准备和执行限制留在自动化工程中，不放入七列用例。

## 确定范围与依据

- 优先结合当前需求、PR、提测说明、已提供的页面和附件。已有足够上下文就直接生成；没有待测功能时才询问。来源无法读取时说明缺口，不编造内容。
- 区分本次验收、必要回归和明确排除项，不把排除项写成必过要求。不猜测未知的按钮名称、页面入口、状态文案或产品规则。
- 只收入从产品页面可以准备或找到前置状态、执行操作并判断结果的功能场景。正常流程、异常、边界、刷新后保留、成员权限和关联页面更新都按实际需求覆盖，不凑数量。
- 对页面上存在但当前没有的数据，可简短写“【待准备】一个显示‘生成失败’且可以重试的角色”。不得写成该数据已经存在，也不得要求修改数据库或人为控制服务器。
- 若场景只能通过内部工具改变状态、伪造页面或制造服务故障来实现，不把它编成主表里的必执行页面用例。确实涉及需求风险时，在交付消息中用产品语言简述待确认事项，不擅自增加技术用例、工作表或附件。
- 短暂状态按实际页面观察，例如“提交后查看角色卡片，再等待生成完成”。不要为观察短暂状态强加暂停后台的要求，也不要要求凭手速操作。确实无法观察或缺少需要的页面记录时，如实说明该检查点尚未验证，不据此宣称产品失败。

## 固定七列

主工作表命名“测试用例”，从 A1 开始，严格按以下顺序。除用户要求外，不增加状态、执行人、实际结果或技术准备列。

| 列 | 内容规则 |
| --- | --- |
| 用例编号 | 文本 `TC-001`、`TC-002` 等，编号唯一。修订保留原编号，补充续号；独立重生成版本可重新连续编号。 |
| 用例标题 | 包含主要操作和具体结果，例如“保存角色后弹窗关闭，角色卡片显示生成中”。不用“功能正常”“角色测试”等空泛标题。 |
| 前置条件 | 只写本例需要的页面可见条件，如“当前成员只有查看权限”“列表中有一个生成失败的角色”。省略已登录、环境已部署等通用条件。没有特殊条件则真正留空。需准备的数据用简短的“【待准备】”说明，不放账号绑定、脚本能力、技术复位或成段免责声明。 |
| 输入数据 | 提供具体、可复现的填写值和必要素材信息，如“角色名：QA_蓝色机器人_20261104；图片：robot_front.jpg”。没有输入填“无”。避免每行重复长篇命名规则、工程路径和测试工具配置。 |
| 操作步骤 | 写明页面入口、对象和用户动作；按 `1. `、`2. ` 编号并使用真实换行。引用同一输入名称。要检查刷新、重开或另一成员访问，就写出对应操作。不写调用接口、控制后台、推送事件或检查 Network。 |
| 预期结果 | 写可直接比较的页面结果，如“弹窗关闭；列表出现同名角色，卡片显示生成中；完成后可以点击‘使用’”。避免“数据正确”“权限不变”等笼统结论；不能用成功提示替代刷新后的内容、积分余额或实际访问结果。 |
| 优先级 | 只允许 P0、P1、P2，按下述风险赋值。 |

### 输入和素材

- 使用虚构信息和保留示例域名，不写真实隐私、密码或登录令牌。涉及身份权限时用“工作区所有者”“仅可查看的成员”等产品角色；已有明确测试账号可引用其邮箱，不暴露凭据。
- 普通文本给出具体值。需要避免重名时，写“名称加上本次测试时间”，执行时记录实际名称即可，不在每条用例中重复程序化运行标识的定义。
- 日期使用用户本地日期；时间边界确有业务含义时写清时区及对应业务时点。
- 文件只写与场景有关的名称、真实格式、尺寸、大小等信息；已有文件可引用可用位置，未生成则写“【待准备】”。普通上传不机械要求精确字节、哈希、编码器或完整校验清单；大小边界场景才明确单位与字节数，音视频要求只保留产品实际限制。
- 不把任意虚构数据当作现成可用数据。需要收到邀请时应有可收件的测试邮箱；需要支付时应有明确的测试支付条件。未核实就说明待准备，不声称能自动完成。
- 只编写用例时不声称素材已经生成，也不为凑齐前置条件实际购买、邀请、生成或修改共享数据。

### 合并、拆分与优先级

- 同一输入、操作和前置条件下，顺带可验证的结果合并为一个完整场景。不把保存成功、当前页面显示新内容机械拆成两条；独立的刷新保留、另一页面同步或权限风险仍可单列。
- 不把不同输入边界、权限、失败分支或需要独立准备的数据强行合并。多入口若仅路径不同，可写明确的逐项范围；若每个入口需要重建数据或有不同结果，拆开写。
- P0：核心流程不可用、严重数据丢失或越权等发布阻断风险。P1：主要功能、常见异常、重要边界和保存/同步检查。P2：低频组合及次要体验回归。不要把所有用例都设为 P0。
- 默认按功能分组排列，同组先 P0 再 P1、P2。不插入破坏筛选的空行或合并单元格。用例可独立执行，不写“同上”或依赖上一条执行结果。

## 示例：角色保存后继续生成

- 标题：保存角色后弹窗关闭，角色卡片显示生成中。
- 前置条件：留空；从正常创建入口开始，不额外要求暂停任务。
- 输入数据：角色名 `QA_蓝色机器人_20261104`；图片 `robot_front.jpg`，JPEG，1024×1024，蓝色机器人正面全身图（未有素材时标为待准备）。
- 操作步骤：
  1. 打开角色管理页，点击创建角色，选择从图片创建。
  2. 上传测试图片，填写角色名，点击创建角色。
  3. 查看弹窗是否关闭，并在角色列表找到该名称的卡片。
  4. 查看生成中的卡片，再等待角色生成结束，检查“使用”按钮。
- 预期结果：提交成功后弹窗关闭；列表出现同名角色，生成期间显示生成中；完成后可以点击“使用”。实际按钮和状态文案以核实后的页面为准，不把示例文案当作所有产品的固定标签。

## Excel 生成与交付

- 使用当前可用的 Spreadsheets 技能创建和验证 `.xlsx`，遵循其依赖加载、导出与视觉检查流程。
- 默认一个“测试用例”工作表，固定七列，不合并数据单元格。启用筛选，冻结首行，工具支持时为优先级加 P0/P1/P2 下拉校验。
- 表头清晰，正文顶部对齐并换行。步骤与预期列足够宽，按实际内容调整行高，确保内容不截断；用克制的颜色区分优先级。
- 导出前逐条检查：不懂技术的产品测试人员能否直接照着做？条件是否能在页面查看或通过正常操作准备？每个结果是否有对应页面操作？有没有混入内部字段、技术准备、自动化说明或无依据的产品要求？页面无法验证的内容移出主表，不换个术语继续保留。
- 同时检查七列表头、编号唯一、必要字段完整、无重复场景、优先级有效、步骤使用真实换行；没有特殊前置条件的单元格真正留空。
- 文件名为 `<功能或任务名>_测试用例_<YYYYMMDD>.xlsx`，日期取用户本地日期，保存到本次对话可写输出目录，返回真实可点击文件。
- 交付简短说明总数、各优先级数量及必要的页面数据缺口。说明已编写而非已执行，不承诺全部可自动化。来源链接放在消息中，不额外增加来源列或工作表。解释执行限制也用产品语言，例如“暂时没有可重试的失败角色”，不说“缺少 fixture”。
